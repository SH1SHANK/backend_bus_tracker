# Tracklet ESP32 Hardware Telemetry Protocol Specification

## 1. Overview & Protocol Principles

This document defines the authoritative communication contract between the ESP32 hardware bus trackers and the Fastify telemetry gateway (`backend_bus_tracker`).

Hardware trackers communicate over cellular HTTPS using JSON payloads. Because cellular connections are lossy and microcontrollers experience hardware resets (power cycling, brownouts, watchdog resets), the protocol provides:
1. **Strict Monotonic Ordering**: Packets are numbered sequentially per session (`seq = 1, 2, 3...`).
2. **Reboot Disambiguation via Session Epochs**: Sequence numbers restart at `1` after reboot without colliding with historical packets.
3. **Idempotent Retry**: Network timeouts on both session resets and telemetry transmissions are safely retried with identical identifiers without advancing epochs or duplicating history.

---

## 2. Authentication Endpoint (`POST /api/v1/auth/device`)

Before streaming telemetry, the tracker authenticates using its provisioned credentials to obtain a 12-hour JWT.

### Request
- **Endpoint**: `POST /api/v1/auth/device`
- **Content-Type**: `application/json`
- **Rate Limit**: 10 requests / minute / IP

```json
{
  "device_id": "NITC-BUS-001",
  "secret": "IntegrationSecret1234!"
}
```

### Request Fields
| Field | Type | Constraint | Description |
|---|---|---|---|
| `device_id` | `string` | 3 to 64 chars, pattern `^[A-Za-z0-9_-]+$` | Hardware tracker identifier labeled on the device. |
| `secret` | `string` | 16 to 128 characters | High-entropy pre-shared key provisioned into firmware. |

### Success Response (HTTP 200 OK)
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 43200
}
```

### Error Responses
- **HTTP 401 Unauthorized**: `{ "ok": false, "code": "invalid_credentials", "message": "invalid device credentials" }`
- **HTTP 400 Bad Request**: Validation failure (e.g. secret shorter than 16 characters).
- **HTTP 429 Too Many Requests**: Rate limit exceeded.

## 3. Session Reset Endpoint (`POST /api/v1/auth/reset-session`)

Every time the ESP32 boots or restarts, it must negotiate a new tracking session before emitting telemetry.

### Why `session_id` and `epoch` Exist
- **`seq`**: Identifies a packet's sequential position within a single boot session.
- **`epoch`**: Identifies the current boot session. Allows packet numbering to restart at `seq = 1` without colliding with packets sent prior to the reboot.
- **`session_id`**: A unique random nonce generated by the tracker at boot. If the cellular network drops the HTTP 200 response, the tracker retries with the **same `session_id`**, allowing the server to recognize the retry and return the established epoch without incrementing it again.

### Request
- **Endpoint**: `POST /api/v1/auth/reset-session`
- **Content-Type**: `application/json`
- **Rate Limit**: 10 requests / minute / IP

```json
{
  "device_id": "NITC-BUS-001",
  "secret": "IntegrationSecret1234!",
  "session_id": "boot-1728901234-a8f9c2",
  "reason": "cold_boot"
}
```

### Request Fields
| Field | Type | Constraint | Description |
|---|---|---|---|
| `device_id` | `string` | 3 to 64 chars | Hardware device identifier. |
| `secret` | `string` | 16 to 128 chars | Device secret for authentication. |
| `session_id` | `string` | 1 to 128 chars | **Mandatory** random nonce generated once per boot. Reused on retries. |
| `reason` | `string` | Optional, max 100 chars | Reason for reset: `"cold_boot"`, `"watchdog_reset"`, `"manual_restart"`. |

### Success Response: Initial Negotiation (HTTP 200 OK)
```json
{
  "ok": true,
  "code": "SUCCESS",
  "epoch": 2,
  "device_id": "NITC-BUS-001",
  "bus_id": "412d0b2c-fa7e-4b2b-a584-7368976c367d",
  "idempotent_retry": false
}
```

### Success Response: Idempotent Retry (HTTP 200 OK)
When retrying with the same `session_id` after a network timeout:
```json
{
  "ok": true,
  "code": "SUCCESS",
  "epoch": 2,
  "device_id": "NITC-BUS-001",
  "bus_id": "412d0b2c-fa7e-4b2b-a584-7368976c367d",
  "idempotent_retry": true
}
```

## 4. Telemetry Ingestion Endpoint (`POST /api/v1/telemetry`)

Transmits live GNSS fixes to the backend.

### Request
- **Endpoint**: `POST /api/v1/telemetry`
- **Headers**:
  - `Authorization: Bearer <device_jwt>`
  - `Content-Type: application/json`
- **Rate Limit**: 30 requests / minute / device

```json
{
  "device_id": "NITC-BUS-001",
  "seq": 1,
  "epoch": 2,
  "timestamp": "2026-10-14T07:30:00.000Z",
  "latitude": 11.321456,
  "longitude": 75.934567,
  "speed": 22.5,
  "heading": 90.0,
  "accuracy": 4.2
}
```

### Permitted Nullable GNSS Metrics
If the GNSS receiver has a 2D fix without speed, heading, or accuracy data, those fields may be sent as `null`:
```json
{
  "device_id": "NITC-BUS-001",
  "seq": 2,
  "epoch": 2,
  "timestamp": "2026-10-14T07:30:05.000Z",
  "latitude": 11.321500,
  "longitude": 75.934600,
  "speed": null,
  "heading": null,
  "accuracy": null
}
```

### Telemetry Field Rules & Bounds
| Field | Type | Valid Range / Format | Description |
|---|---|---|---|
| `device_id` | `string` | Must match JWT `sub` | Hardware device identifier. |
| `seq` | `integer` | 0 to $2^{53}-1$ | Strictly increasing sequence number within current epoch. |
| `epoch` | `integer` | 1 to $2^{53}-1$ | **Mandatory** session epoch received from `/reset-session`. |
| `timestamp` | `string` | ISO 8601 (`YYYY-MM-DDTHH:mm:ss.sssZ`) | GNSS UTC fix timestamp. Clock drift tolerance: $\le 15\text{ min}$ old, $\le 1\text{ min}$ future skew. |
| `latitude` | `number` | `11.200000` to `11.450000` | Kozhikode / NITC transit corridor. |
| `longitude` | `number` | `75.800000` to `76.100000` | Kozhikode / NITC transit corridor. |
| `speed` | `number \| null` | 0 to 120 km/h | Ground speed in km/h. |
| `heading` | `number \| null` | 0 to 360 degrees | Course over ground. 360 is normalized to 0. |
| `accuracy` | `number \| null` | 0 to 500 metres | Horizontal dilution of precision / estimated accuracy. |

## 5. Response Semantics & Status Code Mapping

### Response Shape (HTTP 200 OK)
```json
{
  "ok": true,
  "stored": true,
  "state_updated": true,
  "events": []
}
```

| Response Field | Type | Meaning |
|---|---|---|
| `ok` | `boolean` | `true` indicates the request was accepted and processed. |
| `stored` | `boolean` | `true` if a new row was inserted into `bus_positions`; `false` if it was an idempotent duplicate retry. |
| `state_updated` | `boolean` | `true` if `bus_current_state` was updated with fresh coordinates. |
| `reason` | `string?` | Optional explanation (e.g. `"duplicate"` on retry). |
| `events` | `array?` | Transit events generated by the packet (e.g. stop arrivals, departures, route deviations). |

### Complete HTTP Status Code Mapping
| HTTP Status | Error Code (`code`) | Cause | Firmware Action |
|---|---|---|---|
| **200 OK** | `SUCCESS` | Packet accepted and stored. | Advance sequence (`seq++`), emit next fix. |
| **200 OK** | `DUPLICATE_PACKET` | Exact duplicate of already stored packet (`stored: false`). | Safe acknowledgment. Advance sequence (`seq++`). |
| **401 Unauthorized** | `unauthorized` / `UNAUTHORIZED_DEVICE` | Token expired, invalid secret, or device deactivated. | Re-authenticate via `/auth/device`. If 401 persists, device is revoked; halt. |
| **403 Forbidden** | `device_mismatch` | `device_id` in body does not match JWT `sub`. | Fix firmware configuration bug. |
| **409 Conflict** | `STALE_EPOCH_PACKET` | Packet epoch is older than current session in database. | Call `/auth/reset-session` to re-synchronize epoch. |
| **409 Conflict** | `OUT_OF_ORDER_PACKET` | Packet `seq` is lower than last accepted sequence. | Discard dropped packet; emit current fresh fix. |
| **409 Conflict** | `SEQUENCE_REUSE_CONFLICT` | Same `(epoch, seq)` resubmitted with conflicting data. | Firmware bug: sequence was reused. Re-sync via reset-session. |
| **422 Unprocessable** | `outside_service_area` | GPS coordinates outside NITC transit corridor. | Verify GPS fix validity (wait for satellite lock). |
| **422 Unprocessable** | `timestamp_in_future` | GPS timestamp is skewed into the future (> 60s). | Synchronize GPS RTC time before transmitting. |
| **422 Unprocessable** | `poor_accuracy` | GPS accuracy exceeds 500 metres. | Wait for better satellite constellation. |
| **422 Unprocessable** | `gps_jump` | Implied speed between consecutive fixes is impossible. | Check GPS multipath/drift. |
| **429 Rate Limited** | `rate_limited` | Exceeded 30 packets / minute. | Increase telemetry transmission interval ($\ge 2\text{s}$). |
| **500 Internal Error**| `internal_error` | Gateway or database outage. | Exponential backoff retry (1s, 2s, 4s, 8s). |

## 6. Firmware Implementation Guide (Language-Independent)

> [!NOTE]
> Physical ESP32 firmware source code lives outside of the `backend_bus_tracker` repository and has not been executed in this environment. Firmware developers must follow this reference logic.

### Firmware State Variables
- `device_id`: Constant string provisioned in NVS (e.g. `"NITC-BUS-001"`).
- `secret`: Constant string provisioned in NVS ($\ge 16$ characters).
- `jwt_token`: String in RAM (refreshed every 10 hours).
- `session_id`: String generated once at boot (e.g. `"boot-" + millis() + "-" + random()`).
- `current_epoch`: Integer in RAM initialized via `/reset-session`.
- `current_seq`: Integer in RAM starting at 1.

### Firmware Execution Pseudocode

```text
function on_boot():
    connect_cellular_network()
    
    // 1. Generate unique session ID for this boot cycle
    session_id = "boot-" + get_rtc_epoch() + "-" + get_random_hex(6)
    
    // 2. Perform Session Reset Handshake with Retry
    while true:
        response = http_post("/api/v1/auth/reset-session", {
            "device_id": device_id,
            "secret": secret,
            "session_id": session_id,
            "reason": "cold_boot"
        })
        
        if response.status == 200:
            current_epoch = response.json.epoch
            current_seq = 1
            break
        elif response.status == 401:
            log_critical("Device credentials rejected! Halting.")
            halt()
        else:
            wait_exponential_backoff()

    // 3. Obtain JWT Token
    obtain_jwt_token()

function telemetry_loop():
    while true:
        wait(2000) // 2-second sampling interval
        
        gps_fix = read_gps_receiver()
        if not gps_fix.has_lock or gps_fix.accuracy > 500:
            continue // Skip poor accuracy fixes
            
        payload = {
            "device_id": device_id,
            "seq": current_seq,
            "epoch": current_epoch,
            "timestamp": gps_fix.timestamp_iso,
            "latitude": gps_fix.latitude,
            "longitude": gps_fix.longitude,
            "speed": gps_fix.speed_kmh,
            "heading": gps_fix.heading_deg,
            "accuracy": gps_fix.accuracy_m
        }
        
        // Send packet with idempotent retry
        retry_count = 0
        while retry_count < 3:
            response = http_post_with_jwt("/api/v1/telemetry", payload)
            
            if response.status == 200:
                // Successfully stored OR duplicate acknowledged
                current_seq = current_seq + 1
                break
            elif response.status == 401:
                // Token expired - refresh and retry
                obtain_jwt_token()
                retry_count = retry_count + 1
            elif response.status == 409:
                // Epoch or sequence out of sync - reboot handshake needed
                on_boot()
                break
            elif response.status == 422:
                // Bad fix or out of bounds - discard this fix and move to next
                current_seq = current_seq + 1
                break
            else:
                // Network timeout or 5xx - retry with SAME current_seq and SAME payload
                retry_count = retry_count + 1
                wait(1000)
                
        if retry_count >= 3:
            // Network dropped; discard un-ack'd fix and increment seq to maintain monotonicity
            current_seq = current_seq + 1
```
